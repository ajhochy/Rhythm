## S2 frozen reducer contract

Import `emptyTranscript`, `applyTranscriptEvent`, `mergeTranscriptPage`, `settleTranscript` and `TranscriptState` from `gateway/transcript-reducer.ts`. Initialize one reducer state **per local session**, seeded via `mergeTranscriptPage(emptyTranscript(), session.messages, {mode:'merge',hasMore:session.transcriptHasMore??false,nextCursor:session.transcriptCursor})`. Feed actual ordered WS frames unmodified (`part.messageID`/`part.id` on snapshots; top-level delta IDs), preserving order across event kinds in the S2 queue. Merge periodic/older/compaction pages (use `older:true` only for `loadOlder`); explicit revert/fork/summarize replacement uses `mode:'replace'`. Render `state.messages`, key rows by `uiKey ?? id`, and carry `state.cursor`/`state.hasMore` to the session's pagination fields; use `contentRevision` only for message/alias/visible block changes (metadata-only updates leave it unchanged), and `reconciliationNeeded` to request a new page. `settleTranscript` clears pending/streaming but retains unconfirmed optimistic rows on idle; it never starts timers. Only WS parts stream; REST rows never stream, and numeric REST notices sort using `createdAt` (cross-host clock skew ceiling). Producer may pass `receivedAt` in milliseconds on delta for 60s expiry (without a clock, capacity bounds still apply); `generation` on `session.status` advances only for an explicitly known new generation. Permission/question cards remain outside transcript and the existing security boundary; reducer ignores their frames (identical state ref). Unknown/error frames are no-ops; error status remains S2 store responsibility. Do not pretend the S1 module is wired into the live store yet.
