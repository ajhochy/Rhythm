**Cross-workstream contract (permission surfacing, WS1↔WS3):** the bridge forwards
engine `permission.asked` / `permission.replied` to clients over the existing WS
gateway as events carrying `{sessionId, permissionID, directory, tool, patterns,
title}`; REST fallback `GET /agent-sessions/:id/pending-permissions` and
`POST /agent-sessions/:id/permissions/:permissionID/reply` proxy the engine with
correct directory scoping (per #1341 a non-matching triple is a 404, never `true`).
WS1 owns the server side; WS3 builds UI against this contract.

**Conflict hotspots (orchestrator resolves at integration):** `agents_controller.dart`
(WS2/WS3/WS8), chat tool-part rendering (WS3/WS6/WS9), `app.ts` route registration and
`migrations.ts` appends (WS5/WS6/WS10 — additive, order-independent).
