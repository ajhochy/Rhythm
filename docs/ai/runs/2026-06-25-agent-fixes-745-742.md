## Notes

**#745 design:** `managerAgentNameResolver` is an injected callback (not a hard dep on `AgentConfigsController`) so tests can omit it and existing construction sites outside main.dart need no changes. The resolver is called lazily per-turn, never at construction — so it naturally picks up profile changes after a refresh.

**#742 delegation depth decision:** raising to 2 enables the 3-level chain without any profile-specific hardcoding. The `isManager` check at each level is the real guard; the depth cap is a ceiling for misconfigured profiles. See `docs/ai/decisions/2026-06-25-delegation-depth.md`.

**Secretary prompt:** the updated `~/.config/opencode/agents/secretary.md` routing rule is picked up at session creation by the opencode engine (file is read fresh each time, not cached in DB). No DB re-sync needed. Existing open sessions see the old prompt until reopened.

**Provider order:** `AgentConfigsController` moved above `AgentsController` in `main.dart` MultiProvider. Safe — nothing between the two providers reads `AgentsController`. `AgentTriggerWatcher` still correctly reads `AgentsController` via `ctx.read<AgentsController>()` (line 402), which remains available as it was registered just before.

**Visual smoke gap:** `AgentSelectorPill` label/color not pixel-verified — requires manual `flutter run`. Unit tests cover the controller-level behavior (label source, dispatch value, null fallback).
