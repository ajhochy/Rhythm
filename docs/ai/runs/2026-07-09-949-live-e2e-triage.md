## Root causes and fixes

Live E2E against the running backend surfaced five distinct root causes,
fixed in order of discovery:

1. **Stale bundled fork binary.** The vendored `apps/opencode_bin/opencode`
   was built Jul 4, predating the #948 fork patches — `/config/reload` didn't
   exist yet and `reloadConfig()` silently no-op'd. Rebuilt via
   `bun run build --single` in `apps/opencode_fork/packages/opencode`, staged
   at `apps/opencode_bin/opencode`, ad-hoc signed, version-verified as
   `0.0.0-issue-949-harvest-to-file-202607090326`.

2. **Provider-only agent configs stalled turns forever.**
   `resolveModelFromAgentConfigs` required both `provider_id` and `model_id`
   to be set; when an agent config had only a provider (`model_id: null`),
   resolution failed and `ws_gateway` dropped the turn with only a WS error
   frame, leaving the session stuck in `starting` indefinitely. Fixed in
   `agent_model_resolver.ts`: a provider-only config now falls back to a
   known-good pin (`openrouter` -> `openrouter/free`, with a ponytail comment
   noting #930's `DEFAULT_MODEL_BY_PROVIDER` supersedes it on merge), then to
   the engine's `config.providers()` default map via the new
   `getDefaultModel(providerId)` in `opencode_client_service.ts`.

3. **Engine default map picks an image model for openrouter.** The engine's
   `config.providers()` default for `openrouter` resolves to
   `google/gemini-3-pro-image-preview` (the first catalog entry), which
   errors at `SessionPrompt.createUserMessage` for a text turn. Pinned
   `openrouter/free` ahead of the engine default map (see #2).

4. **Distill rode global MRU instead of the session's model.** `distill`
   picked up whatever model was most-recently-used machine-wide
   (`anthropic/claude-opus-4-7` on this machine), violating the live test's
   no-paid-Anthropic design. Fixed in `skill_extractor.ts`: `LlmCall` gained
   an optional `model` param, and distill now rides the extracting session's
   own backfilled model instead of the global MRU.

5. **`triggerSkillReload` invalidated the wrong engine instance.** The fork's
   `/skill/reload` `directory` param keys the **engine instance** (session
   cwd), not the skills path. Passing `managedSkillsRoot()` invalidated an
   instance no session runs in, so fresh drafts stayed invisible via
   `GET /opencode/skills`. Fixed: `triggerSkillReload` now calls
   `reloadSkills()` argless.

## Operational notes

- Server runs on `:4000` in this environment; the test's default is `:4001`
  — use `RHYTHM_LIVE_URL` to point at the running instance.
- `queueSkillExtraction` silently **drops** during the ~90s engine
  cold-start window. This is an operational precondition for live runs, not
  a bug: don't queue extraction until the engine is warm.
- The harness's #949 phase can flake when `openrouter/free` rate-limits turn
  2. The test can't see WS error frames when that happens, so it reads as a
  hang rather than a rate limit. #930's fallback chain (already implemented
  on `issue-930-model-fallback-chain`, awaiting gated live smoke) is the
  systemic fix for this class of flake.
