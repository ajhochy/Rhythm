## Decisions

- The relay authenticates the phone Device credential and checks its user and host against the active Mac uplink. The Mac remains the authority for project, ticket, and PTY ownership. Local 401/403/404 denials become 4401/4403 terminal closes through the uplink.
- Established PTY sockets revalidate the same device on input, output, and a one-second idle interval. A revoked device closes with 4401. Established Mac uplinks periodically revalidate their bearer and fail closed if validation fails or stalls.
- Frame and socket buffers have explicit byte caps. Operator logs retain a bounded identifier and error class; they do not include credential values, host paths, or terminal content.
- The live proof uses a generated synthetic fixture and `tools/dev/sandbox.sh up --foreground` on isolated ports 4198, 4197, 4299, and 4200. No production bearer, hosted account, installed app service, or user data is used.

## Threat-model review

The trust boundaries are phone → relay (Device verifier and active host/user), Mac → relay (uplink bearer and repeated validation), and relay → Mac (original Device credential and short-lived PTY ticket, with project/PTY ownership checked again on the Mac). A valid second user's device on the same host is denied before any PTY frame reaches the Mac. A valid user's ticket for another project is closed with 4403 by the Mac, and the relay preserves that code for the phone. Revocation after the PTY opens closes the established phone socket with 4401. The relay does not need the model-held credential for these paths. Remaining review scope is the actual hosted Cloudflare deployment and mobile behavior during a real network interruption.
