## What was built

- **Contract:** `CoordinatorCalendarMirrorProjection` / `CoordinatorProjectSessionsProjection` as OPTIONAL adapter slots and optional projection fields; scope gains optional `sessionId` (current Secretary root). They are excluded from `mandatoryModelContextIsQualified` and from the model-context byte measure; an optional failure is an explicit state, never absence or a blocked chat.
- **Calendar (owner-local cached mirror):** reads only the exact owner's Google account (`findByProviderAsync`), the raw stored selection JSON (exact `integration_preferences` row; the preferences repository collapses corrupt to "missing", so a narrow local raw SELECT in the adapter distinguishes them — no repository edited) and the read-only window method added to `CalendarShadowEventsRepository`. States: `observed`, `not_configured` (no owner account → leftover mirror never shown), `account_unavailable`, `never_synced`, `invalid_sync_time` (unparseable or future), `preferences_corrupt`, `disabled_by_selection` (explicit empty list), `read_failed`, `changed_during_read`. Always `accountBinding:'unproven'`, `externalCompleteness:'unknown'`, `totalCount:null`, observed `lastSuccessfulSyncAt`/`syncAgeSeconds` (no freshness TTL). After the mirror read the account id/owner/external id/status/lastSyncedAt AND the raw selection are re-read (awaited); any difference withholds the projection. Window = today through the next seven America/Los_Angeles days; timed rows overlap by normalized instants (spanning events included), all-day rows by civil days with exclusive end, ordering by normalized start then id (never raw ISO order across offsets), eight selected plus a one-row lookahead → `hasMore`; a 1,000-row candidate-scan cap also forces `hasMore`. Output is title (control characters removed, ≤160 chars), start/end/allDay and an opaque calendar label (`primary calendar`, or `calendar-xxxxxx` when the id looks like an email) — no description, location, account email, credentials, scopes or raw errors. No `ensureFreshAccount`/sync/settings/provider call; asserted `fetch` unused and `total_changes()` unchanged.
- **Project sessions:** the existing `listPage` (chats, archives off, no search/project selector), at most 2×100 rows and 12 selected roots. Strict `ownerUserId === owner` (NULL/foreign rejected), root/nonsystem/nonarchived, current Secretary root excluded, real nonarchived project plus the injected existing `ownerProjectAccess`, rechecked for every selected row at exposure. Grouped by project; opaque ids, bounded labels, persisted status, lastActivityAt, actual profile id/label; `codingWorkflow` only for the exact `workflow-orchestrator` id; missing/disabled/locked profile → `executionAvailable:false` historical status. Coverage is `recent_window_exhausted` or `recent_window_truncated` (budget exhausted, cursor expired or more eligible rows) — never an exact total/all-projects claim. No transcripts, previews, cwd, provider account, permissions/grants, resumable state or legacy child counts; no dispatch grant.
- **Delivery:** `foregroundSystemContract` adds compact state/coverage/sync-age/count qualifications only (no event/session bodies) plus one sentence on how to treat them and to use the existing signed `rhythm_get_coordinator_status` only if actually granted; the server preface sentence says the existing tool also carries these observations. `modelStatusText` adds bounded observations with deterministic fixed-step trimming (events/sessions 8/12 → 4/6 → 2/3 → 0/0, always rebuilt as valid JSON, `…OmittedForSize` counts) and the oversize fallback keeps both sources' state/coverage. Fingerprint adds a semantic `optionalSources` block (ids/titles/windows/status/profile fields, last sync time) that excludes the ticking sync-age clock and is `undefined` (hash unchanged) when neither source is composed. The existing foreground `current` check and the callback `prepare/current` seam therefore observe source changes with no new hook.

## Byte caps, truncation, identity and completeness limits

- Caps: calendar 8 observations (+1 lookahead, 1,000-row scan cap), titles ≤160 chars (status ≤80), project sessions 12 roots / 2×100 pager rows, signed status ≤3,800 UTF-8 B (the existing bound), model context ≤8,000 B measured WITHOUT the optional sources (their own caps bound them, ~3 KB each worst case).
- Truncation is always explicit (`hasMore`, `recent_window_truncated`, `…OmittedForSize`); counts are never exact totals (`totalCount:null`).
- Account identity: the mirror has no external account binding; an in-place Google reconnect keeps the row id/lastSyncedAt and the old mirror. The projection says so (`accountBinding:'unproven'`) and a change DURING the read is withheld; a change BEFORE the read cannot be detected. External completeness is unknown even for an empty window (one-page sync, no receipt). A sync-provenance receipt would be a separate, separately accepted improvement.
- The pager snapshots all matching ids internally, so "bounded" means bounded output/selection, not bounded SQL.
- Hosted/PostgreSQL: the local window method throws (SQLite-only) → `read_failed`; no hosted claim.
