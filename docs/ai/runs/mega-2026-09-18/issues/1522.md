# #1522 Electron Agents: add a project directly from the Agents tab [OPEN] labels=bug,frontend

## Problem
AJ reports there is no way to add an agent project from the Electron Agents tab. Existing project/session grouping does not provide an accessible project-creation flow.

This concerns **agent projects associated with local working directories**, not the separate operational Projects tab covered by #1517. The broken directory Browse control in the detailed/advanced session creation inspector is already tracked in #1496 and is a related usability blocker.

## Current evidence
- `SessionRail.tsx` loads project labels and derives displayed project groups from sessions. Its primary actions create sessions/open advanced session creation; no Add project action is exposed.
- `apps/web/src/gateway/sessions.ts` exposes project labels and branch operations, but does not expose project creation in that interface.
- The existing agent-project backend already has `ProjectsController.create`: name + working directory, optional icon, directory normalization, duplicate-directory rejection, and VCS discovery.
- Flutter has an established agent-project model and controller under `features/agent_projects/`; use those flows as a functional reference.

## Acceptance criteria
- [ ] Provide an obvious Add project action in the Agents tab, including when no projects or sessions exist.
- [ ] Let the user provide a project name and choose a working directory using the native directory picker from #1496, with manual path entry available as an alternative.
- [ ] Create through the existing agent-project API and preserve its directory validation and duplicate-project rules. Show understandable validation/error feedback and prevent duplicate submissions.
- [ ] After successful creation, the project appears and can be selected immediately even before it has any sessions. It remains available after refresh/relaunch.
- [ ] Starting a session in the selected project uses the intended project identity and working directory; existing sessions and their grouping remain correct.
- [ ] Canceling the form or directory picker creates nothing and preserves existing selection. The project-creation flow must not automatically run an agent, initialize instructions, switch branches, or modify files in the selected directory.
- [ ] Keyboard access, loading/empty/error states, long names/paths, and the new project's empty-session state are usable.

## Likely files

- `apps/web/src/components/AgentsWorkspace.tsx` and the session creation/store wiring as needed

## Required evaluation
Use isolated synthetic data and a disposable directory to verify add → visible empty project → refresh → start session with the correct directory/project binding. Cover duplicate/invalid paths, picker cancel, failed save, and keyboard use. Exercise the real existing API/session flow in the sanctioned dev sandbox; fixture-only rendering does not prove persistence or binding.

## Dependencies / related work
Reuse the native picker from #1496; keep its advanced session-creation fix covered as well. Coordinate Agents layout with #1513. This issue is distinct from #1517's operational project UI.

## Safety / out of scope
Issue filing only. No implementation, live project/session creation, automatic agent turns, filesystem initialization, backend restart, production data repair, or deployment is requested here. Preserve existing permissions, worktree rules, and API semantics.
