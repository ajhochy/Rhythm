# #1512 Electron Agents: replace oversized child-loading buttons with compact tree controls [OPEN] labels=enhancement,frontend

## User report

AJ rejects the appearance of the Agents sidebar's child-session loading controls: “i also hate this. it looks so out of place in the UI.”

The September 17 screenshot shows stacked, full-width outlined buttons with bold, centered, multiline labels such as `Load children of [long parent session title]`. These read like large call-to-action cards inside a compact session tree, repeat information already present in the parent row, and displace actual conversations.

## Current implementation

`apps/web/src/components/SessionRail.tsx` renders a generic `.secondary-button` for each parent whose children have not been loaded or whose child page has more results. Its visible label is `Load children of ` or `Load older children of ` followed by the full session name.

Long titles therefore turn a pagination control into several lines of prominent text. This is a presentation/wording problem; child-history loading must remain available.

## Proposed change

Replace the large outlined buttons with a compact, left-aligned continuation row that belongs visually to the session tree:

- **Load subagents** for the initial load; **Load more subagents** for subsequent pages. Use “older” only if the ordering contract actually guarantees that meaning.
- Indent/group the control under its parent at the same level as that parent's child rows.
- Use regular-weight, readable secondary text and a small disclosure/loading indicator. Avoid repeating the parent title visibly, heavy outlines, card treatment, and centered multiline text.
- Retain the parent name in the accessible name so multiple loading controls are distinguishable to screen-reader users.
- Provide compact loading, retry/error, and end-of-results behavior without changing session selection or unexpectedly moving the user's reading position.

Use a rail-specific treatment rather than restyling all `.secondary-button` controls across the app.

## Acceptance criteria

- [ ] The screenshot's stacked multiline outlined buttons are replaced by visually subordinate, compact tree controls.
- [ ] Long parent titles do not expand the visible loading label into a large block; parent context remains clear through grouping and accessibility text.
- [ ] Both initial child loading and pagination remain discoverable and functional, including nested parents and multiple parents with similar names.
- [ ] Loading/error/retry states are clear; repeated activation does not duplicate requests or rows, and the continuation control disappears when no more results exist.
- [ ] Loaded children, counts, ordering, expansion, selected session, and scroll position remain correct.
- [ ] Keyboard operation, focus visibility, accessible parent-specific names, existing minimum hit-area requirements, narrow rails, both themes, and 200% zoom remain usable. Compact visuals must not mean a tiny click target.
- [ ] AJ reviews before/after screenshots of the same long-title, nested-session case in the actual Electron app.
