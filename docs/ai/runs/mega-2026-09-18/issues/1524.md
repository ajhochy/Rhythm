# #1524 Electron app-wide: make every view pane and column resizable by dragging [OPEN] labels=enhancement,frontend

## Request — app-wide UI rule
AJ requests that **all view panes and columns be resizable by clicking and dragging their divider, across every page, tab, and screen in Rhythm Electron**. This is a universal interaction rule, not a feature limited to Agents or the current list/inspector redesigns.

## Scope
Cover every existing multi-pane/column view: app navigation and sidebars, item lists, center workspaces, detail inspectors, previews/artifacts, terminal panes, nested horizontal/vertical splits, and multi-pane dialogs or creation screens. Include every tab/state that reveals a different pane arrangement.

Inventory all routes from `App.tsx`, including Agents, Dashboard, Planner, Tasks, Rhythms, Projects, Messages, Facilities, Automations, Integrations, Profiles, Endpoint Map, Mobile Access, main Settings, and every Agent Tool/Agent Settings view. This list is a starting point; hidden, nested, and newly added layouts must follow the same rule.

## Current evidence
`AgentsWorkspace.tsx` already supports horizontal resizing of the session rail and inspector, including keyboard-operable separators. `SessionRail.tsx` has a vertical Tools-panel resize handle. These are useful references, but they are page-specific and do not establish app-wide coverage.

## Acceptance criteria
- [ ] Produce a route/tab/screen inventory identifying every pane boundary and verify each one. No multi-pane screen is exempt merely because it uses a different component or stylesheet.
- [ ] Every boundary between adjacent view panes/columns can be resized by click-drag. Side-by-side columns resize horizontally; stacked panes resize vertically. Nested splits work independently.
- [ ] Use a shared splitter/layout implementation with consistent hit areas, appropriate resize cursors, hover/focus feedback, and smooth drag behavior throughout the app.
- [ ] Provide useful resizing ranges with minimum sizes that keep essential controls usable. Neighboring panes reflow correctly; no overlap, inaccessible actions, or accidental whole-window horizontal overflow.
- [ ] Keep dragging reliable when the pointer leaves the divider or crosses embedded content such as artifact frames. Release/cancel always ends the gesture; no stuck drag, unintended text selection, or leaked pointer listeners.
- [ ] Remember user-selected pane sizes across navigation, reopening a view, and app relaunch using stable layout-specific preference keys. Provide an accessible reset to sensible defaults.
- [ ] Reconcile saved sizes with available window space, zoom, collapse/expand, and responsive layout changes. Restore useful dimensions when a pane reappears.
- [ ] Each splitter is keyboard-operable with visible focus, an accessible name/orientation, and meaningful current/min/max size information. Keyboard and pointer adjustments use the same bounds.
- [ ] Resizing preserves selection, unsaved edits, scroll usability, and ongoing session state. It must not recreate the selected record or trigger an application action.
- [ ] Content that depends on container size, including terminals, editors, calendars, and artifact previews, responds correctly to pane resizing.
- [ ] Document this as a shared UI requirement so future pages/tabs/screens inherit resizable panes rather than introducing new fixed-width splits.

## Required evaluation
Add reusable rendered splitter tests plus an explicit coverage matrix for all routes, tabs, and multi-pane screens. Test pointer and keyboard resizing, nested horizontal/vertical splits, minimum sizes, long content, embedded frames, terminal reflow, window/zoom changes, collapse/reopen, remembered dimensions, and reset. Verify representative flows in the actual Electron app. One working Agents divider is not evidence that the app-wide requirement is complete.

Issue filing only at this stage. This work changes presentation and local layout preferences, not domain data, permissions, API semantics, or session execution. No implementation, live-service restart, production data changes, or deployment is requested here.
