# #1520 Electron packaging: replace the generic Electron app icon with the Rhythm icon [OPEN] labels=bug,frontend

## Problem
AJ reports that the packaged Electron app displays the generic Electron app icon instead of the Rhythm icon.

Expected: the distributed `Rhythm.app` uses the existing Rhythm branding in Finder, the Dock, the macOS app switcher, and Get Info.

## Source evidence
`apps/electron/scripts/package-mac.mjs` copies `node_modules/electron/dist/Electron.app` into the staging bundle, renames the executable, and replaces the bundle name, identifier, and version metadata. It does not currently stage a Rhythm `.icns` resource or replace `CFBundleIconFile`. This appears to leave the upstream Electron icon in the packaged bundle.

Existing Rhythm icon artwork is available in `apps/desktop_flutter/macos/Runner/Assets.xcassets/AppIcon.appiconset/` at sizes from 16 to 1024 pixels. Reuse the established artwork rather than introducing a new icon design.

The reported artifact version/build was not captured. The earlier test launch in this session also used the development Electron binary, so verification must distinguish that launcher from a freshly packaged `Rhythm.app`.

## Acceptance criteria
- [ ] The macOS packaging pipeline includes the correct multi-resolution Rhythm icon and sets the bundle icon metadata to that resource.
- [ ] The packaged app's primary icon is the Rhythm icon, with no fallback to the generic Electron icon.
- [ ] A freshly packaged/installed app displays the Rhythm icon in Finder, Dock, Command-Tab, and Get Info, at normal and Retina sizes.
- [ ] The release pipeline uses the same icon assembly step; the icon is present before app signing/notarization, with no post-signing bundle modification.
- [ ] Packaging fails clearly if the required Rhythm artwork or generated icon is absent/invalid.
- [ ] Add a focused packaging regression check for the referenced icon resource and Rhythm artwork identity/content, not merely the existence of an arbitrary `.icns` file.

Inspect the actual packaged `Contents/Info.plist` and icon resource, run the focused packaging check, and visually inspect the packaged app on macOS. Record the build/commit and bundle path. Account for macOS icon caching during verification; a development `electron .` launch alone does not qualify the packaged icon. Verify that normal bundle signing checks still pass.
