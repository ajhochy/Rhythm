# #1523 Electron agent profiles: redesign settings and actions while preserving the existing page structure [OPEN] labels=enhancement,frontend

## User clarification
AJ says the Agents tool/profile page structure is good, but the settings/functions UI for each profile is poor. **Preserve the existing profile list and selected-profile editor/inspector structure.** This is a focused redesign of the controls and actions inside each profile, not another page-layout replacement.

## Current evidence
`apps/web/src/components/Profiles.tsx` already has a searchable/selectable profile rail and a profile editor. The editor contains Identity, Delegation, Availability, Provider & model, Capabilities, and Core permission rules. The live capabilities UI renders lists of MCP tool and skill checkboxes, while live core permissions are exposed as a raw JSON textarea. These are concrete starting points for the control-design pass; this report does not establish that their backend behavior is broken.

## Acceptance criteria
- [ ] Retain the existing profile-list/inspector arrangement and selection flow. Focus changes on each profile's settings, functions, and action presentation.
- [ ] Make the selected profile easy to understand at a glance: clear identity/status, meaningful section hierarchy, aligned labels/controls, readable descriptions, consistent spacing, and restrained visual treatment.
- [ ] Give identity/instructions, provider/model/account, delegation, availability/defaults, capabilities, and permissions coherent groups with plain-language explanations where needed. Frequently used controls should be easy to find; advanced details should remain discoverable without overwhelming the editor.
- [ ] Make long MCP/tool and skill lists manageable through clear grouping, selection summaries, and filtering or disclosure as appropriate. Preserve complete access to individual choices and communicate inherited/explicit selections accurately.
- [ ] Provide understandable controls for common permission choices rather than requiring raw JSON for ordinary edits. Preserve full existing policy semantics, including inheritance, per-tool patterns, and advanced/unknown entries; retain an explicit advanced editing path where necessary and never silently flatten or discard policy data.
- [ ] Place profile-level actions consistently, with clear distinction between normal editing, immediate actions, and destructive actions. Preserve all existing profile functions and their authorization/confirmation requirements.
- [ ] Make save/cancel, unsaved changes, validation, saving, success, and failure states unambiguous. Switching profiles must not silently discard edits or apply them to the wrong profile.
- [ ] Preserve actual live behavior and persistence for each setting. Fixture-only controls must not be presented as working live functionality.
- [ ] Ensure keyboard navigation, focus, labels, read-only states, long content, and smaller windows remain usable; sticky actions must not cover fields.
