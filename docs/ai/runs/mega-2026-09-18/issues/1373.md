# #1373 OCU-35B/use-case-1: Cloudflare relay for Tailscale-free mobile session connectivity [OPEN] labels=status:partial

Vertical slice of #1177 (remote-workspace execution). Product trigger: mobile off-LAN connectivity is brittle when it depends on a `*.ts.net` Tailscale path; route the paired session transport through a Cloudflare relay instead.

## Workflow
Operator: church staff on the mobile app, off the local network. They open/continue an agent session whose engine runs on the paired Mac, reaching it through a Cloudflare relay rather than Tailscale. Recovery: relay drop reconnects idempotently to the same session.

## Where this touches today (from prior exploration)
- Paired gateway is `127.0.0.1:4002` (not 4001); the desktop already validates cloud bearers via production `/auth/me`.
- Mobile `safeGatewayUrl` hard-codes `.ts.net` — the relay path must be a first-class alternative, not a Tailscale assumption.
- Device tokens exist precisely because "the model holds the bearer" is the threat model — the relay must preserve that boundary.
- The iOS spec already pre-plans a Cloudflare relay on the same transport contract; reuse that contract.

## Acceptance (inherits #1177)
- [ ] Mobile connects to its paired session transport through the Cloudflare relay with **no** Tailscale dependency, and the existing SSE/PTY/prompt contract is unchanged.
- [ ] Auth boundary preserved: device-token/cloud-bearer validation unchanged; the relay never sees or needs a raw model-held bearer; fail closed on invalid/expired/revoked tokens.
- [ ] Relay endpoints are authenticated and tenant/project-scoped; opaque IDs; cross-user/cross-project fail closed.
- [ ] Disconnect/relay-drop recovery is idempotent — resume the same session or show a durable actionable failure, never duplicate.
- [ ] Explicit kill switch; disabling the relay falls back to the existing paired path with no data loss.
- [ ] Observability records operator/session/relay state + sanitized failure reason, no credentials/host paths/transcript content.
- [ ] Threat-model review + a negative test from a second user/project proving denial.
