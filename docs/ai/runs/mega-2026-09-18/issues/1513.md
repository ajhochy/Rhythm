# #1513 Electron Agent Tools: unify every tool around the Agents Tasks list-and-inspector pattern [OPEN] labels=enhancement,frontend

## Request
Unify every Agent Tools page around the layout AJ prefers in Agents → Tasks.

## Reference and shared design contract
AJ explicitly selected **Agents → Tasks** as the visual and interaction reference (not the main Tasks tab). The shared pattern is:
- A compact item list on the left: a simple title and one short subtitle/metadata line.
- Selecting a row opens that item's full details and functions in the main inspector to its right (the center workspace when the app navigation is visible).
- Keep the list for selection; put detailed content, editing, and item-specific actions in the inspector.
- Use the same typography, spacing, row selection, inspector structure, and action placement across these pages. Preserve each domain's actual functions.

## Scope and current evidence
`SessionRail.tsx` lists Brain, Deep Research, Tasks, Webhooks, Profiles, Skills, Playbooks, Cookbook, Review Queue, Report Card, Email, and Gallery. `ToolWorkspace.tsx` contains mixed list, split, report, and gallery presentations; Profiles has its own component. `LiveSchedulesTool` is the reference with `.tool-split`, `.tool-rail`, and `.tool-detail`.

Apply the shared pattern to every tool, including specialized report/artifact views by keeping their detailed content in the inspector. Agent Settings configuration coverage is tracked separately, but must use this same pattern.

## Acceptance criteria
- [ ] Inventory every exposed Tools entry and include an explicit before/after checklist so no tool is missed.
- [ ] Every tool presents selectable compact title/subtitle rows and a main inspector containing the selected item's details and existing functions.
- [ ] Reuse a common layout/row/inspector contract rather than creating page-specific variants of the same pattern.
- [ ] Keep Agents → Tasks as the baseline and preserve its scheduling, history, and action behavior. Do not copy an existing defect merely to achieve visual parity.
- [ ] Preserve specialized editors, artifact previews, review actions, and profile controls within the consistent structure.
- [ ] Mouse and keyboard selection update the correct inspector, with visible focus and selected state.
- [ ] Long titles/metadata, empty results, loading, errors, and read-only access remain usable; resizing does not clip essential controls.
- [ ] Refresh and existing deep links preserve or restore the correct selection; missing/deleted items produce a clear state rather than stale details.
