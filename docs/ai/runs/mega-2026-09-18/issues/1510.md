# #1510 Mobile and Electron: unwanted low-frequency bell during agent turns [OPEN] labels=bug,frontend

## User report

AJ reports that **both the mobile app and the Electron desktop app play an audible low-frequency bell/ringing sound while an agent is running a turn**.

This issue records the reported behavior; the sound has not yet been independently reproduced or attributed on either client. Do not assume both clients share the same cause.

## Expected behavior

Routine text-agent processing should be quiet unless the user explicitly enables a working/processing sound. An existing mute or working-sound-off preference must be respected throughout the turn and after relaunch. Preserve intentional speech playback and configured approval/completion alerts.

## Reproduction to confirm

1. On mobile, start a normal text turn long enough to observe the running state and listen for the reported low-frequency bell.
2. Repeat in Electron.
3. Test each client independently and identify which device/process emits the sound; also test with both connected to the same running session.
4. Record client/build, foreground/background state, voice mode, sound preference, whether the ring repeats, and whether it coincides with streaming, tool events, pending approvals, reconnects, or completion.
5. Toggle the relevant sound preference off, repeat the turn, and verify it remains off after relaunch.

Reported environment: the Electron candidate launched September 17 was a local build from checkout `4103f54c`, using interactive mode with the existing Flutter-owned API on 4001 and engine on 4096. Keep that runtime arrangement in mind when attributing desktop audio. The exact mobile build and per-device sound settings were not captured with this report.

## Source-backed investigation leads

### Mobile

- `apps/mobile/lib/voice/working-sound.ts` synthesizes a 1.8-second tone and plays it with `isLooping: true`. The `soft` variant mixes approximately 261.63, 329.63, and 392 Hz tones.
- `apps/mobile/providers/opencode-provider-utils.ts` declares defaults of `workingSoundEnabled: true`, variant `soft`, and volume `0.18`.
- `apps/mobile/providers/opencode-provider.tsx` starts that sound when native mobile is busy and working sounds are enabled, excluding listening/speaking phases.
- Settings expose “Soft chime” and “Glass tone” in `apps/mobile/components/settings/settings-utils.ts` / `settings-sections.tsx`.

This is a plausible source of the mobile report, not a confirmed runtime diagnosis. Inspect whether normal text turns should enter this path by default and how existing saved preferences are handled.

### Electron

- `apps/electron/src/main.mjs` creates native notifications for pending approvals; inspect notification lifecycle/deduplication and OS sound behavior if timing correlates with the ring.
- Inspect `apps/web/src/components/Shell.tsx`, `apps/web/src/store.tsx`, and relevant notification/session event handling for the actual triggering path.
- No equivalent Electron working-sound loop has been established by the initial source inspection. Check OS notifications, terminal/tool output, other connected clients, and the Flutter-owned runtime as alternatives rather than assuming a shared implementation.
