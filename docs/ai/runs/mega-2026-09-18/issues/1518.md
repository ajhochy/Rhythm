# #1518 Electron Automations: adopt the Agents Tasks list-and-inspector design [OPEN] labels=enhancement,frontend

## Request
Bring the Electron Automations tab into the unified Agents → Tasks visual and interaction pattern.

## Design reference
AJ explicitly selected **Agents → Tasks** as the visual and interaction reference (not the main Tasks tab). The shared pattern is:
- A compact item list on the left: a simple title and one short subtitle/metadata line.
- Selecting a row opens that item's full details and functions in the main inspector to its right (the center workspace when the app navigation is visible).
- Keep the list for selection; put detailed content, editing, and item-specific actions in the inspector.
- Use the same typography, spacing, row selection, inspector structure, and action placement across these pages. Preserve each domain's actual functions.

## Current context
Automations already has grouped rule content and a separate inspector/direct editor. Simplify the rule list and make the inspector the consistent place for full rule configuration and actions.

## Acceptance criteria
- [ ] Show compact automation rows with name and short status/source/trigger metadata; use lightweight grouping or filtering where useful.
- [ ] Selecting a rule displays trigger, conditions, action, account, and other supported settings in the main inspector.
- [ ] Keep existing create, edit, enable/pause, preview, history/details, and delete functions where supported. Keep item-level actions in the inspector and global creation in the page toolbar.
- [ ] Selecting or inspecting a rule must never execute it. Preserve unavailable/read-only states and confirmation requirements.
- [ ] Mouse and keyboard selection update the correct inspector, with visible focus and selected state.
- [ ] Long titles/metadata, empty results, loading, errors, and read-only access remain usable; resizing does not clip essential controls.
- [ ] Refresh and existing deep links preserve or restore the correct selection; missing/deleted items produce a clear state rather than stale details.

Include rendered checks for keyboard focus, long titles, narrow windows, loading/empty/error states, and consistent appearance alongside Agents → Tasks. Existing domain behavior must continue to pass.
