# #1521 Electron main Settings: adopt the Agents Tasks list-and-inspector design [OPEN] labels=enhancement,frontend

## Request
AJ requests that the main Rhythm Settings tab receive the same UI overhaul as Facilities, Messages, Projects, Automations, and Integrations.

The reference is **Agents → Tasks**, as explicitly confirmed by AJ: a compact item list on the left, with a simple title and short subtitle/metadata; selecting an item opens all of its details and functions in the main inspector to the right (the center workspace when app navigation is visible).

This issue covers the main `/settings` page. Agent Settings configuration coverage is tracked separately in #1514.

## Current evidence and scope
`apps/web/src/pages/settings/index.tsx` currently renders a sequence of sections containing controls directly on the page:
- Appearance and keyboard
- Workspace and members
- Notifications
- Accounts and access
- Runtime and updates

Organize these existing settings into the shared list-and-inspector structure. Keep categories/items easy to scan and put full descriptions, current values, forms, and actions in the selected inspector. Workspace-member details should remain easy to select and manage within this structure without crowding the navigation rows.

## Acceptance criteria
- [ ] Main Settings uses the same list width, typography, spacing, selected-row treatment, inspector hierarchy, and action placement as the shared design in #1513.
- [ ] Each left-hand row has a clear title and one short explanatory subtitle or useful status; detailed forms and actions appear in the main inspector after selection.
- [ ] All existing settings and functions remain reachable: appearance, keyboard/safety preferences, workspace information, join-code management, members/roles, Facilities Manager access, notifications, account/access destinations, sign-out, runtime health/version, and release access.
- [ ] Current values are loaded from the appropriate existing source, and edits retain their existing persistence scope. Clearly distinguish device/user preferences from workspace administration.
- [ ] Preserve admin-only permissions, self-management restrictions, relevant confirmations, and disabled/pending/error feedback. Selecting a row must not itself change a setting or execute an action.
- [ ] Related destinations such as Agent Settings, Integrations, Mobile Access, and memory remain discoverable without duplicating their entire editors into main Settings.
- [ ] Mouse and keyboard selection work with visible focus and selected state. Long labels, smaller windows, and scrolling do not hide essential controls.
- [ ] Loading, unavailable, empty, and read-only states are clear; switching sections does not silently discard unsaved edits or show stale details.
