# #1514 Electron Agent Settings: expose the missing agent configuration controls in a list-and-inspector layout [OPEN] labels=bug,frontend

## Problem
AJ reports that Agent Settings does not expose the agent-menu configurations. Source inspection supports a concrete gap: `LiveSettingsTool` displays profile name/provider/model summaries plus Auto-promotion, but does not offer the full configuration controls. The Flutter settings sheet includes Accounts, Behavior, Keybindings, OpenCode Server, and MCP sections.

## Design reference
AJ explicitly selected **Agents → Tasks** as the visual and interaction reference (not the main Tasks tab). The shared pattern is:
- A compact item list on the left: a simple title and one short subtitle/metadata line.
- Selecting a row opens that item's full details and functions in the main inspector to its right (the center workspace when the app navigation is visible).
- Keep the list for selection; put detailed content, editing, and item-specific actions in the inspector.
- Use the same typography, spacing, row selection, inspector structure, and action placement across these pages. Preserve each domain's actual functions.

## Acceptance criteria
- [ ] Inventory the existing agent-menu configuration entries and Flutter settings controls; record their Electron destinations and identify missing functionality explicitly.
- [ ] Provide a compact left list of configuration sections/items and show their actual current values, explanations, and supported controls in the main inspector.
- [ ] Restore access to the applicable Accounts, Behavior, Keybindings, runtime/server, and MCP configurations, alongside profile-related configuration and existing Auto-promotion controls. Reuse working configuration surfaces where available.
- [ ] Clearly distinguish agent/profile, desktop-local, and workspace settings. Do not present a profile summary as the configuration editor.
- [ ] Load and save through the existing responsible service, with validation, pending state, failure feedback, and persistence after reopening. Unsupported capabilities must be explained rather than implemented as no-op controls.
- [ ] Preserve authorization, credential handling, destructive-tool approval behavior, and Auto-promotion eligibility/confirmation gates.
- [ ] Mouse and keyboard selection update the correct inspector, with visible focus and selected state.
- [ ] Long titles/metadata, empty results, loading, errors, and read-only access remain usable; resizing does not clip essential controls.
- [ ] Refresh and existing deep links preserve or restore the correct selection; missing/deleted items produce a clear state rather than stale details.
