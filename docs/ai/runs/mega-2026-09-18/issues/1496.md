# #1496 Electron: native directory picker for agent project selection (Browse) [OPEN] labels=

## Problem

`SessionRail`'s "Browse…" button for picking an agent project directory is disabled whenever a live gateway is connected (`apps/web/src/components/SessionRail.tsx` ~line 347): `disabled={liveHistory}`, with the fixture-only fallback setting a hardcoded `/workspace/rhythm` path. Under the live gateway (the normal case), users must hand-type an absolute path with no picker at all.

The Flutter desktop app already solves this natively: `apps/desktop_flutter/lib/features/agents/views/agents_view.dart` calls `FilePicker.getDirectoryPath()` to open the OS directory picker. Electron has no equivalent.

## Proposed minimal design

- `apps/electron/src/main.mjs`: add an IPC handler that calls `dialog.showOpenDialog({ properties: ['openDirectory'] })` and returns the selected path (or null on cancel).
- `apps/electron/src/preload.cjs`: expose one narrow `selectDirectory()` method via `contextBridge` — no broader filesystem surface.
- `apps/web/src/components/SessionRail.tsx`: enable "Browse…" whenever `window.electron?.selectDirectory` (or equivalent) is present, call it, and fill the `cwd` field with the result. Keep manual path entry as the fallback when the API is absent (e.g. running in a plain browser) — do not remove it.
- Add security-test coverage for the new IPC surface (the repo already has an IPC/security-smoke pattern in `apps/electron/src/security-smoke-receipt.mjs` and related tests) — assert the exposed API is scoped to this one method and returns only a path string, no arbitrary filesystem access.

## Out of scope

- No change to the fixture/demo path behavior (`liveHistory` fixture fallback stays as-is).
- No broader file-system bridge — directory selection only.
