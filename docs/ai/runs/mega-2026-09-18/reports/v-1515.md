# Decisions

- Chose one prefixed `facilityItemId` query key so rooms and reservations share a stable selection contract; rejected separate unsynchronized room and reservation query states.
- Kept the fixture Overview and Rooms controls as meaningful list filters; rejected removing the existing schedule/room context.
- Grouped fixture reservations by date and rooms by building, while the live list combines building groups with the selected room's reservations; rejected page-specific forks of `ListInspector`.
- Loaded live recurring-series summaries with the page load so selecting a room only changes UI selection; rejected a selection-triggered gateway fetch.
- Kept all existing confirmations and mutation gateway calls; rejected moving mutation behavior into the shared primitive.
