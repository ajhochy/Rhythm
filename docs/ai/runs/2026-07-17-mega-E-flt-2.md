## #1074 (OCU-33) — native-tool permission tri-state matrix — DONE

- New collapsed-by-default "Tool Permissions" `RhythmDisclosure` section in
  `AgentProfileSheet`, one tri-state row (Ask/Allow/Deny, unset = engine
  default) per known opencode core permission key (read, edit, glob, grep,
  list, bash, task, external_directory, todowrite, question, webfetch,
  websearch, skill — mirrors `apps/opencode_fork/.../config/permission.ts`'s
  `InputObject`).
- `bash` gets its own row plus a pattern editor (add/re-toggle/remove),
  matching the backend's `Rule = Action | Object` schema; other keys are
  simple actions only (issue only asked for bash pattern support).
- Exotic keys already present but not in the known list (repo_clone,
  repo_overview, lsp, doom_loop, or anything unrecognized) surface in a
  nested "Advanced" disclosure — string-valued exotic keys stay editable via
  the same tri-state control; nested-object exotic keys are shown as a static
  summary (no authoring UI for those, matches the issue's non-goal).
- `AgentConfig` gained an opaque `corePermissionsJson` passthrough field
  (fromJson/toJson/copyWith) — the sheet owns all parsing/building.
- Unset rows are never written: `_corePermissions` only holds keys the user
  touched, and the save payload sends `null` when the map is empty (no
  overrides) or the encoded map otherwise — satisfies "unset rows leave
  frontmatter untouched."
- Live `websearch=Deny` enforcement is a backend guarantee (#1073, already
  merged/live-verified) — not re-verified here since this is a pure Flutter
  cluster against a UI-only change; see #1073's own run log for that
  live-verify evidence.

## #1079 — "Show in agent picker" toggle — DONE (hint nice-to-have SKIPPED)

- New `CheckboxListTile` "Show in agent picker" bound to
  `AgentConfig.sessionSelectable` (field already existed on the model from
  prior work), placed after the Model/Claude Account sections (see placement
  note below). PATCHes `sessionSelectable` on save.
- **Skipped**: the issue's own "Nice-to-have" hint for "scheduled but
  hidden" profiles. That requires wiring `AgentSchedulesController` (a
  sibling feature, not provided in the widget tree at every call site of
  `showAgentProfileSheet`) into this sheet to cross-reference scheduled
  tasks by `agentConfigId`. The backend guard from #1039 already prevents
  scheduling a subagent-only (non-selectable) profile going forward, so the
  hint only helps legacy/already-scheduled edge cases — not worth the
  cross-feature Provider wiring for a nice-to-have. Flagging for a follow-up
  issue if wanted.

## Notes

- **Regression caught and fixed during implementation**: my first pass
  placed the new "Show in agent picker" toggle immediately after the
  Manager/Delegates section (before Model). `agent_profile_model_picker_test.dart`
  uses a fixed 900px-tall host with no scroll-into-view before asserting on
  the Model dropdown — Flutter's `ListView`/Sliver viewport only builds
  children within the viewport + cache extent, so the extra ~70px row pushed
  the Model section's `DropdownButtonFormField` out of the built range and
  broke 3 of that file's tests (0 widgets found, not a hit-test/scroll
  issue — the widget wasn't in the element tree at all). Fixed by moving the
  toggle to *after* the Model/Claude Account sections instead of touching
  the pre-existing test. Root-caused via a throwaway debug widget test
  (`debugDumpApp()` + isolated repro), not guesswork.
- `_PermissionActionSelector` uses Flutter's built-in `SegmentedButton` with
  `emptySelectionAllowed: true` (native widget, no new dependency) — tapping
  the already-selected segment clears it back to "unset."
- Widget-test flakiness lesson recorded: driving multiple sequential
  `pumpWidget()` calls + interactions within a single `testWidgets` body is
  fragile (stale scroll/animation settling between pumps caused a tap-miss
  on the disclosure header in one earlier draft). Split into independent
  `testWidgets` blocks instead, matching this suite's existing one-pump-per-test
  convention.
- No sandbox/backend interaction needed for this run — pure Flutter/UI
  change against already-merged backend contracts (#1073, #1088); no
  `tools/dev/sandbox.sh` startup required per the mandatory workflow (that
  gate applies to backend/API work against the live-shaped server).
