## Precision addendum — bind relay hint and mirror to the device's actual host

Read-only source finding: **host provenance is lost at hub publication and is absent from mirrored session rows.** `GlobalEventEnvelope` (`opencode_event_hub.ts:28`) and `EventsEnvFrame` (`relay_uplink_protocol.ts:87`) carry only the existing envelope. `relay_uplink_server.ts:747` publishes the received envelope unchanged; the hub queues and drains that same object. Session model/repository and replicated full rows have no authenticated machine/host identity. The trusted provenance exists only on `UplinkConnection` (`relay_uplink_server.ts:58/:600/:659`): authenticated user plus validated/enrolled hello machine ID. The message callback verifies `this.active === connection` at :684, but `handleFrame(frame)` then discards the connection parameter. `isHostOnline(H1,user)` alone cannot bind a queued H2 event or an old H2 mirror row to H1.

Exact smallest internal correction for the relay writer:

- Pass the already authenticated `connection` into `handleFrame(frame, connection)` at :685; capture its validated hostId, authenticatedUserId and an unforgeable internal connection-generation token. Never read provenance from an event payload or supplied row field.
- Before existing `this.hub.publish(frame.envelope)` at :748, associate the **same envelope object** with that origin in a relay-instance `WeakMap<object, Origin>`. Expose a narrow origin-reader to the route-injected relay qualifier. The existing hub preserves object identity, so this metadata survives queue/drain without adding serialized keys, changing external envelopes/protocol, or retaining a new event queue. Apply-produced recovery hints get the same trusted origin when minted after successful replication apply.
- Track provenance for the currently qualifying mirrored primary **local row ID** only when an authenticated `agent_sessions` upsert actually applies successfully. The small current-root provenance index is bounded by current qualified roots, contains no bodies, and is invalidated on row deletion/archival/disqualification and active connection/host change. A missing origin is a drop; do not retroactively assign the current host to pre-existing SQLite rows. Persisted replica content alone is not host proof. This is internal qualification state, not a new replicated table, protocol, timer or retry queue.
- At the write boundary require **eventOrigin.hostId === mirrorOrigin.hostId === currentDevice.hostId**, **eventOrigin.userId === mirrorOrigin.userId === currentDevice.userId === attachedOwner**, and event/mirror generation equal the current authenticated connection generation. Then require `isHostOnline(currentDevice.hostId,currentDevice.userId)` plus the existing exact current device id/token, project/local-root/conversation/primary checks. A host/generation switch after enqueue must reject the old object even if the old device is still authenticated and user/project/local IDs happen to match.

To make new qualifying hints recover through the existing seam, ensure each qualifying canonical producer dirties that root's **existing agent_sessions outbox record** before its hint can be forwarded, including bridge output when its normal write only dirties `agent_session_messages`. The outbox already reads full live rows and coalesces pending records; no new table/protocol is needed. The successful agent_sessions apply establishes origin and emits the recovery hint described above. Do not stamp origin on a duplicate/non-applied seq, speculate from a resync-done marker, or adopt rows from an earlier host merely because their IDs match.
