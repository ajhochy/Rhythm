# Chat settings wire addendum — Sol for Astra review

2026-10-06. Addendum to the accepted `rhythm-chat-controls-parity-plan.md`; source inspection only, no implementation or tests. Synthetic examples are frozen in `rhythm-chat-settings-wire-fixtures.json`. Runtime hold was released at **03:10:41 UTC**; builder still owns activation and fresh idle checks. Existing source establishes desktop local-ID PATCH/readback and mobile SDK-only/full-state PATCH; the versioned mobile behavior below is proposed, not installed.

**Exact target and existing port.** Desktop keeps `sessions.patchSettings(localId, changedFields)` → `PATCH /agent-sessions/:localId`, then the existing `GET /agent-sessions/:localId?transcriptLimit=50` authoritative readback. Rhythm uses its actual canonical local root; ordinary chat uses its selected local session. Mobile reuses `/mobile-gateway/sessions/:id/state` with explicit query `identity=local-primary` or `identity=sdk`. Add GET on that same path for canonical state/capability, and partial-settings PATCH for those explicit selectors. Both retain `requireMobileDevice`, project scope and `X-Rhythm-Project-ID`. No selector means the existing legacy SDK/full-profile PATCH semantics; unknown selectors are 400, never a fallback lookup.

For `local-primary`, `:id` is exactly **`MobileCoordinatorBinding.sessionId`**, the server-issued local root, for either paired-catalog or server-primary binding. Never use `uiSessionId`, `actorKey`, `currentSessionId`, SDK ID or synthetic view key. API uses `findById` and the existing read-only designated-primary/current-root checks: exact device owner, current authorized nonarchived project, nonarchived primary root and eligible selected profile. Do not call a create-if-absent resolver. No SDK row is required or created. For `sdk`, `:id` is the actual ordinary catalog SDK ID; use `findBySdkSessionId` and existing owner/project admission. Root selector additionally requires exact project equality; the legacy helper's null/blank-project allowance is not primary authority. Unauthorized, missing or replaced targets are 404. Reprove target/profile/model/project across awaited model authorization before commit and readback.

**Changed fields only.** Explicit-selector PATCH accepts a nonempty subset of `modelMode`, `providerId`, `modelId`, `thinkingBudget`, `fastMode`; reject other fields. Fixed selection is exactly `{modelMode:'fixed',providerId:<nonempty>,modelId:<nonempty>}` with existing authorized provider/model resolution. Provider/model alone, partial pair, null tuple, or tuple with Auto are 400. Auto is exactly `{modelMode:'auto'}` and preserves stored fallback tuple. Reasoning is `thinkingBudget:null` or a nonnegative integer. Fast is boolean, including explicit false. Omissions preserve exact persisted values; opening/switching writes nothing. Never send profile/agent/permission/account fields through this settings-only contract or apply profile defaults. Mobile's existing low/high mapping applies only to an explicit reasoning edit; a model/Fast edit must preserve any exact existing budget, including 2048. Auto does not enable or qualify Kev; unsupported provider controls retain existing capability behavior. No new tier enum.

**Response and compatibility.** Explicit-selector GET/PATCH returns the existing safe state plus required `settingsContractVersion:1`, `settingsIdentity:'sdk'|'local-primary'`, `sdkSessionId:string|null`, `fastMode:boolean`. Existing `localSessionId`, profile/agent/availability, model tuple/mode, router timestamp, exact thinking budget and permission mode remain canonical. SDK response must echo its requested SDK ID; primary response must echo requested local ID and may have null SDK. Legacy responses may omit the additions: omitted Fast means unknown, never false or a write-back default. A successful PATCH's complete returned canonical state is its readback; no redundant GET needed.

Before enabling the new editor, GET must prove version 1 and exact identity. Old API 404/unsupported/missing version disables local-primary settings (especially no-SDK roots) and Fast; never redirect to ordinary selection or manufacture an SDK. Ordinary known-SDK sessions may retain their existing legacy model/reasoning full-state path, using authoritative existing state, retaining profile/grants and omitting Fast entirely. No automatic retry of a failed v1 PATCH through legacy. After every await, provider rechecks captured paired-client/generation, project and visible binding/SDK target before applying response; stale responses cannot overwrite a newly selected chat. Rejection retains current display/draft and surfaces the error. These checks are UI currency, not server authorization.
