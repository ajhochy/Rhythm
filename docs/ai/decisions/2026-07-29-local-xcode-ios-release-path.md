# Local Xcode archives are a supported iOS path; simulator is not a valid OAuth smoke target

## Context

The Rhythm Agents iOS release path was EAS-only (`npm run eas:production:ios`
→ preflight → build → auto-submit, remote frozen credentials). Two things
forced a local-Xcode path this run: EAS was being bypassed deliberately, and
the App Store Connect app record turned out not to exist, so a cloud build
would have had nothing to submit to anyway.

Two facts surfaced that are worth recording because both cost real time.

**Expo is the app, EAS is optional.** `apps/mobile` is 69 TypeScript/TSX
files with zero hand-written Swift/ObjC/Kotlin — React Native 0.81.5 on Expo
SDK 54 with 29 `expo-*` native modules. Expo cannot be dropped without
rewriting the app. EAS, by contrast, is only a cloud build/submit service:
`expo prebuild` + `pod install` + `xcodebuild archive` + `-exportArchive`
produces an equivalent, distribution-signed IPA locally.

**But bypassing EAS does not bypass the production config gate.**
`app.config.ts` and `scripts/release-preflight-ios.mjs` both hard-fail without
an exact Google mobile OAuth client. That guard runs during prebuild and
bundling regardless of who drives the build.

**The simulator cannot exercise Google sign-in.** `expo-auth-session`'s
`promptAsync` presents `ASWebAuthenticationSession`, which asks SpringBoard to
open `SafariViewService`. On the simulator this is refused:

```
FBSOpenApplicationErrorDomain code 3 ("Security")
"Un-trusted clients may not open applications in the background."
Open "com.apple.SafariViewService" request from RhythmAgentsDev failed
```

`promptAsync` then never resolves and the UI sits on "Completing sign-in…"
indefinitely. Relaunching the app by tapping its home-screen icon (rather than
via `expo run:ios`) does **not** clear it — the refusal reproduced on a
tap-launched process.

## Decision

1. **Local Xcode archive/export is a supported iOS build path**, alongside
   EAS. To keep it repeatable, `ios.appleTeamId` is committed in
   `app.config.ts` (env-overridable via `EXPO_APPLE_TEAM_ID`). Without it a
   local archive fails with "Signing for RhythmAgents requires a development
   team", and because `ios/` is regenerated by every prebuild, a command-line
   `DEVELOPMENT_TEAM=` had to be repeated on every build. `ios.appleTeamId` is
   consumed by `@expo/config-plugins`' `DevelopmentTeam` plugin, which writes
   `DEVELOPMENT_TEAM` into both build configurations.
2. **EAS remains the preferred release path** (`eas:production:ios` chains
   preflight → build → auto-submit with remote frozen credentials, which is
   what #1198 expects). Local Xcode is for fast iteration, device debugging,
   and verifying build-output properties like the app icon.
3. **Google sign-in is smoked on a physical device only.** Do not spend time
   diagnosing OAuth on the simulator; the failure is an environment sandbox
   restriction, not an app defect. The simulator remains useful for launch,
   tab structure, navigation, and icon verification.

## Alternatives considered

- **Force a production archive with a placeholder client ID.** Rejected: it
  satisfies the regex but embeds a non-existent OAuth client, so sign-in
  breaks at runtime for every TestFlight tester — worse than no build, and the
  config's stated contract forbids it.
- **Keep `DEVELOPMENT_TEAM` as a command-line flag.** Rejected: silently
  lost on every `prebuild --clean`, so every local build rediscovers the same
  failure.
- **Commit the generated `ios/` directory to pin Xcode settings.** Rejected:
  `/ios` is gitignored by design (Continuous Native Generation). Native
  settings belong in `app.config.ts` or a config plugin — which is why
  transport security is the `withTransportSecurity` plugin rather than a plist
  edit.
- **Work around the simulator OAuth refusal.** Rejected as sunk cost: the
  real app was already confirmed working on hardware, so the only thing under
  test was the simulator.

## Consequences

- A local archive now works from a clean checkout with no extra flags:
  `expo prebuild --platform ios` (with `LANG=en_US.UTF-8` for CocoaPods) →
  `xcodebuild archive` → `-exportArchive`.
- `buildNumber` remains a manual concern on the local path. EAS increments it
  remotely (`appVersionSource: remote`); local archives do not, so repeated
  uploads of the same version will be rejected as duplicates until this is
  scripted or bumped by hand.
- The physical-device smoke leg (#1199) is now load-bearing for the auth
  matrix, not optional coverage.
