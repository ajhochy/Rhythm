## Missing capabilities — Flutter has them; React/Electron does not

The corrected parity corpus contains 78 `live-artifacts` mappings: 40 Flutter test declarations, 36 API test declarations, and 2 documentation checks. It contains **zero React or Electron mappings**. That is evidence about declarations, not proof of capability; the source walk below independently confirms eight product gaps.

## Security finding that overrides copy-parity

Phase 8's stated hostile-artifact rule is stricter than the current Flutter network policy and must be treated as the React/Electron contract, not copied mechanically from Flutter.

Flutter blocks non-initial navigation, popup creation, permissions, back/forward gestures, and reports blocked form/download/file/media attempts (`origin/main:apps/desktop_flutter/lib/features/live_artifacts/widgets/live_artifact_view.dart:75-135`; `origin/main:apps/desktop_flutter/lib/features/live_artifacts/services/live_artifact_bridge.dart:23-35`). The API render CSP blocks `connect-src`, forms, frames, objects, and framing (`apps/api_server/src/controllers/live_artifacts_controller.ts:45-70`). However, that CSP still allows scripts/styles/images/fonts from named public CDNs, and Flutter's normalizer preserves those sources (`apps/api_server/src/controllers/live_artifacts_controller.ts:55-56`; `origin/main:apps/desktop_flutter/lib/features/live_artifacts/data/live_artifacts_data_source.dart:10-15`, `origin/main:apps/desktop_flutter/lib/features/live_artifacts/data/live_artifacts_data_source.dart:62-86`). Therefore Phase 8 must prove that an Electron-rendered hostile artifact reaches **no remote or local network at all**, including those allowlisted Flutter CDN origins, and also reaches no file picker/file URL, popup, navigation, form submission, media permission, or download.

The existing Electron shell is a useful outer boundary: it has `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`, and `webSecurity: true`, and denies top-level navigation, popups, permissions, and downloads (`apps/electron/src/main.mjs:138-166`). It is not an artifact renderer: its preload has no artifact bridge and its network request interception is smoke-only and profile-specific (`apps/electron/src/main.mjs:106-136`; `apps/electron/src/preload.cjs:9-23`). Phase 8 needs an artifact-specific isolation boundary and packaged hostile-content evidence.

## Capability detail by family

### Catalog, detail, and render

- **Flutter:** authenticated `GET /live-artifacts?type=html`, `GET /live-artifacts/:id`, and `GET /live-artifacts/:id/render`; render is fetched by the host so artifact code never receives bearer credentials (`origin/main:apps/desktop_flutter/lib/features/live_artifacts/data/live_artifacts_data_source.dart:113-135`, `origin/main:apps/desktop_flutter/lib/features/live_artifacts/data/live_artifacts_data_source.dart:233-242`).
- **React:** fixture session artifacts have a select and sandboxed, scriptless `srcDoc` preview, but selecting/opening only changes local state and a request-log string (`apps/web/src/components/Inspector.tsx:166-183`). There is no live artifact gateway, list, detail, render fetch, or Dashboard destination.
- **API:** all routes are authenticated; list supports `type=html` and optional `search`, detail includes current `state`, render returns generated HTML plus security headers (`apps/api_server/src/routes/live_artifacts_routes.ts:8-21`; `apps/api_server/src/controllers/live_artifacts_controller.ts:27-44`, `apps/api_server/src/controllers/live_artifacts_controller.ts:45-70`).

### Dashboard tabs, picker, lifecycle, and accessibility

- **Flutter:** fixed Dashboard; dynamic, horizontally scrollable, ellipsized artifact tabs; fixed add button; left/right wrap; Delete/Backspace closes; close focuses a neighbor; Escape closes picker and restores focus; opening an already-open artifact selects it (`origin/main:apps/desktop_flutter/lib/features/live_artifacts/widgets/dashboard_artifact_tabs.dart:159-211`, `origin/main:apps/desktop_flutter/lib/features/live_artifacts/widgets/dashboard_artifact_tabs.dart:213-327`).
- **Flutter lifecycle:** stale picker/tab requests are token- and generation-guarded; tab states are `loading`, `ready`, `unavailable`, `deleted`, `conflict`, or `error`; close does not call artifact delete (`origin/main:apps/desktop_flutter/lib/features/live_artifacts/models/live_artifact.dart:88-105`; `origin/main:apps/desktop_flutter/lib/features/live_artifacts/controllers/live_artifacts_controller.dart:140-197`).
- **React:** Dashboard is a planning surface with planning states and has no artifact workspace wrapper (`apps/web/src/pages/dashboard/index.tsx:18-51`, `apps/web/src/pages/dashboard/index.tsx:227-235`).

### State and bundle revisions

- **Flutter user surface:** bridge state reads and writes are CAS-bound by `expectedStateRevision`; viewer reload retrieves fresh detail and render under the same artifact ID (`origin/main:apps/desktop_flutter/lib/features/live_artifacts/services/live_artifact_bridge.dart:89-110`; `origin/main:apps/desktop_flutter/lib/features/live_artifacts/widgets/live_artifact_view.dart:167-211`). Flutter exposes no direct user bundle editor.
- **Agent transport:** MCP exposes list/get/create plus revision-checked state and bundle update tools. Its snake_case tool inputs translate to canonical camelCase API bodies (`apps/mcp_server/src/tools/liveArtifacts.ts:55-105`). Writes pass the outbound-action authorization gate (`apps/mcp_server/src/tools/liveArtifacts.ts:82-84`, `apps/mcp_server/src/tools/liveArtifacts.ts:88-105`).
- **API:** state and bundle revisions are independent compare-and-swap counters. A stale write returns `409`, `error.code: 'CONFLICT'`, and the applicable current revision (`apps/api_server/src/controllers/live_artifacts_controller.ts:77-78`; `apps/api_server/src/repositories/live_artifacts_repository.ts:36-39`).
- **React:** no artifact transport or renderer exists to observe either update.

### Sharing and ownership

- **Read authorization:** owner always reads; `organization` reads require workspace membership; `shared` reads require both workspace membership and collaborator membership; `private` denies non-owner (`apps/api_server/src/repositories/live_artifacts_repository.ts:17-29`). Missing or unauthorized IDs are non-disclosing `404` (`apps/api_server/src/controllers/live_artifacts_controller.ts:20-25`).
- **Mutation authorization:** metadata, collaborator changes, and soft delete are owner-only; bundle/state writes are allowed to any readable actor and are revision checked (`apps/api_server/src/controllers/live_artifacts_controller.ts:73-79`). This is the existing authorization contract Phase 8 must preserve.
- **Flutter:** owner-only sharing dialog described in missing capability 7.
- **React:** no sharing surface or ownership gate found.

### Constrained bridge

- **Flutter:** the accepted envelope keys are exactly `id`, `method`, `params`, and `nonce`; request IDs match `^[A-Za-z0-9_-]{1,64}$`; the payload limit is 64 KiB; maximum in-flight requests are 8; duplicate IDs are rejected (`origin/main:apps/desktop_flutter/lib/features/live_artifacts/services/live_artifact_bridge.dart:20-35`, `origin/main:apps/desktop_flutter/lib/features/live_artifacts/services/live_artifact_bridge.dart:47-83`).
- **Methods:** `state.get`, `state.update`, `pco.services.read`, and the host-internal report `host.blocked`; there is no generic fetch, URL, path, method, shell, filesystem, clipboard, popup, navigation, or download operation (`origin/main:apps/desktop_flutter/lib/features/live_artifacts/services/live_artifact_bridge.dart:23-35`, `origin/main:apps/desktop_flutter/lib/features/live_artifacts/services/live_artifact_bridge.dart:89-125`).
- **Lifecycle binding:** responses from a stale artifact generation are discarded; the only evaluated response script calls the fixed `window.__rhythmHostResponse` with JSON data (`origin/main:apps/desktop_flutter/lib/features/live_artifacts/services/live_artifact_bridge.dart:75-87`, `origin/main:apps/desktop_flutter/lib/features/live_artifacts/services/live_artifact_bridge.dart:143-158`).
- **React/Electron:** no artifact bridge exists. The current generic preload must remain closed rather than acquiring a generic request primitive (`apps/electron/src/preload.cjs:14-23`).

### HTML import

- **Flutter:** import is a real native-file journey with format, size, encoding, preview-title, warning, and explicit private-create behavior. The current decomposer intentionally preserves the entire source as `bundle.html` and supplies empty `css` and `js` (`origin/main:apps/desktop_flutter/lib/features/live_artifacts/services/html_import_decomposer.dart:17-26`).
- **React/Electron:** no implementation found. This capability was not explicit in plan criteria c1-c4 and therefore receives added Phase 8 criteria.

## Scope conclusion

Phase 8 is a React/Electron build phase even though the corrected corpus has 78 mappings. Those mappings prove substantial Flutter and API declarations exist; they do not provide a React/Electron live artifact catalog, Dashboard workspace, persisted tabs, current-bundle renderer, state/PCO bridge, sharing UI, or import journey. The API and MCP transport already establish the canonical IDs, authorization, visibility, revisions, bundle/state shapes, and capability vocabulary. React/Electron should consume those contracts without inventing new literals or a generic privileged bridge.
