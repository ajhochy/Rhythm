# Phase 4 capability inventory — session and transcript lifecycle

Reference: Flutter from `origin/main` at `9fa2761ed78159f83f56982c03fcd85dc035039a`.
React/API evidence is from the current `codex/react-electron-live-suite` worktree on 2026-08-15.
This is a capability inventory, not a count of test declarations.

## Missing in React/Electron

These are capabilities the shipping Flutter client has and the React/Electron client cannot perform against the live boundary today.

1. **List the live `scheduled` and `self_improvement` session scopes.** Flutter maps its three list views to the canonical query values `chats`, `scheduled`, and `self_improvement`, and reloads from the API when the scope changes (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:69-85,1876-1888`; REST construction at `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/data/agents_data_source.dart:322-349`). React exposes tabs named `chats`, `scheduled`, and the non-canonical `background` (`apps/web/src/types.ts:9`; `apps/web/src/components/SessionRail.tsx:116-125,162-165`), but its live gateway always calls `/agent-sessions?scope=chats` and has no scope argument (`apps/web/src/gateway/sessions.ts:20-31,155-158`). The API type permits only `chats | scheduled | self_improvement` (`apps/api_server/src/models/agent_session.ts:28-44`). No React implementation found for live non-chat scope loading.

2. **Keep the live session list synchronized with sessions created elsewhere.** Flutter consumes the shared session list and `session.created` events, filters them to the current canonical scope, and inserts new rows (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:3125-3144`). React's live reducer handles `session.removed`, `session.updated`, `message.part.delta`, `session.status`, and `agent-configs.changed`, but not `sessions.list` or `session.created`; its Refresh action reloads only the selected detail whenever a selection exists (`apps/web/src/store.tsx:159-208,238-247`; `apps/web/src/components/SessionRail.tsx:159`). No React implementation found for a true live list refresh/synchronization path.

3. **Persist close, archive, and restore lifecycle actions.** Flutter sends `DELETE /agent-sessions/:id` for close and `PATCH /agent-sessions/:id` with canonical `archived: true|false` for archive/restore, with server-error recovery (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/data/agents_data_source.dart:639-684`; controller behavior at `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:2334-2438`). React's header “Close session view” only posts a notification, while archive/restore only mutate its local store even in live mode (`apps/web/src/components/AgentsWorkspace.tsx:130`; `apps/web/src/components/SessionRail.tsx:145-149`; `apps/web/src/store.tsx:323-328`). The live gateway exposes no close/archive/restore methods (`apps/web/src/gateway/sessions.ts:20-31`).

4. **Pick real local files and deliver them to the provider as structured parts.** Flutter uses the native file picker, resolves MIME from extension/content, truncates text at 100 KB, emits image/PDF `data:` file parts or safe binary `file:` references, and sends `session.input.parts` (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/views/agents_view.dart:2306-2414`; `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/views/_attachment_mime.dart:103-131,178-222`; `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:2526-2568`). React offers only five hard-coded fixture files, even in live mode (`apps/web/src/components/Composer.tsx:8-16,70-101,166`), and `sendLiveInput` discards its `attachments` argument and sends only `data` plus an optional model override (`apps/web/src/store.tsx:278-303`). The API already accepts `parts` and forwards them verbatim, with a 20 MB file guard (`apps/api_server/src/services/ws_gateway.ts:287-350,829-852,913-928`). No React implementation found for a real file chooser or live `parts` transmission.

5. **Accumulate a complete partial response while it streams.** Flutter appends every `message.part.delta` to the existing part and synthesizes an assistant bubble when the first live part arrives (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:3190-3221,3442-3464,3560-3603`). React adds a part key to `streamedPartsRef` on the first delta and returns immediately for every later delta with the same session/message/part key, so only the first text fragment is visible until the idle REST refresh (`apps/web/src/store.tsx:175-203`). The bridge explicitly broadcasts every delta (`apps/api_server/src/services/opencode_stream_bridge.ts:1345-1399`).

6. **Consume and render structured live and reloaded transcript parts without flattening them.** Flutter preserves part types and fields for `text`, `reasoning`, `tool`, `step-start`, `step-finish`, `compaction`, `file`, and `agent`, then dispatches reasoning, tool, compaction, agent, and attachment renderers (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/models/chat_models.dart:119-132,174-239,255-339`; `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/views/agents_view.dart:1725-1841,1986-2022`). React ignores live `message.part.updated` and `message.updated`, and its REST mapper converts every persisted part to `kind: 'markdown'` using only `text` or `content` (`apps/web/src/store.tsx:159-208`; `apps/web/src/gateway/sessions.ts:77-91`). Although React has fixture-only rich block renderers (`apps/web/src/components/Transcript.tsx:11-20`), no React implementation maps canonical live part objects into them.

7. **Page older persisted transcript messages.** Flutter stores the returned cursor/has-more state and calls `GET /agent-sessions/:id/messages?limit=50&before=<cursor>` to prepend earlier structured messages (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/data/agents_data_source.dart:375-411`; `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:2860-2879`; load-earlier UI at `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/views/agents_view.dart:880-889`). The API returns canonical `pageInfo.nextCursor` and `pageInfo.hasMore` (`apps/api_server/src/controllers/agent_sessions_controller.ts:2369-2393`; repository window at `apps/api_server/src/repositories/agent_session_messages_repository.ts:503-534`). React's “Load older messages” calls a fixture helper that invents one local system message; its gateway has no transcript-page method (`apps/web/src/components/Transcript.tsx:69`; `apps/web/src/store.tsx:333`; `apps/web/src/gateway/sessions.ts:20-31`).

8. **Cancel a real in-flight turn.** Flutter calls `POST /agent-sessions/:id/cancel` and clears working state only after success (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/data/agents_data_source.dart:628-637`; `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:2159-2170`). The API resolves the local ID to the SDK session and calls `abortSession` (`apps/api_server/src/controllers/agent_sessions_controller.ts:1508-1525`). React's live cancel buttons call the fixture `cancelSession`, which only changes local fields; the live gateway has no cancel method (`apps/web/src/components/Composer.tsx:151`; `apps/web/src/components/SessionRail.tsx:148,164`; `apps/web/src/store.tsx:328`; `apps/web/src/gateway/sessions.ts:20-31`).

9. **Resume the existing SDK conversation and handle a missing SDK session honestly.** Flutter posts to `/agent-sessions/:id/resume`, rehydrates the transcript immediately, and exposes the server's 410 “start fresh” condition when the persisted SDK session is gone (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/data/agents_data_source.dart:687-695`; `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:2361-2392`). The API distinctly reattaches by `sdkSessionId`, returns 410 when that engine session no longer exists, and only creates a new SDK session for legacy rows lacking the ID (`apps/api_server/src/controllers/agent_sessions_controller.ts:1736-1804`). React's `resumeSession` only changes local group/status fields and never calls the endpoint (`apps/web/src/store.tsx:327`; `apps/web/src/components/SessionRail.tsx:147`; `apps/web/src/gateway/sessions.ts:20-31`).

10. **Reconnect automatically, retain outbound input during an outage, resubscribe, and rehydrate.** Flutter distinguishes an actually ready socket from a channel object, queues up to 50 frames, reconnects with 250 ms–30 s exponential backoff, flushes in order, reports overflow, and on explicit reconnect sends `session.subscribe` then refetches the transcript (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/data/agents_data_source.dart:64-99,167-305`; `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:1779-1788,2500-2519`). React queues only while the initial socket is `CONNECTING`, drops the queue on close, has no close/error reconnect loop, and never resubscribes or refetches on socket recovery (`apps/web/src/gateway/sessions.ts:168-182`; mount-only connection at `apps/web/src/store.tsx:151-228`). Its visible Reconnect controls drive fixture/local state (`apps/web/src/components/AgentsWorkspace.tsx:127`; `apps/web/src/components/Composer.tsx:144`; `apps/web/src/store.tsx:355-363`).

11. **Show provider retry state with attempt and reason.** Flutter retains `{attempt, reason}` from canonical `session.status` frames whose `status` is `retrying`, clears it on progress, and renders an inline retry indicator (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:229-232,3156-3201`; `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/views/agents_view.dart:964-1020`; `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/views/_retrying_indicator.dart:13-77`). The bridge sends `status: 'retrying'`, `attempt`, and `reason` (`apps/api_server/src/services/opencode_stream_bridge.ts:1534-1563`). React's wire type does not declare `attempt` or `reason`, and its reducer collapses every status frame to `working`/`idle` (`apps/web/src/gateway/sessions.ts:4-18`; `apps/web/src/store.tsx:197-203`).

12. **Open live child-session transcripts using the parent local ID and child SDK ID.** Flutter resolves an already-persisted child by `sdkSessionId` when possible and otherwise fetches `/agent-sessions/:parentLocalId/children/:childSdkId/messages`, keeping the identity layers distinct (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:1143-1149`; `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/data/agents_data_source.dart:800-827`; tool rendering/navigation at `origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/views/agents_view.dart:1872-1900`). React's child navigation searches fixture `Session.id`/`parentId` values and only changes local selection; the live mapper always returns `childIds: []`, and the gateway exposes no children/messages endpoint (`apps/web/src/components/Transcript.tsx:54-60`; `apps/web/src/gateway/sessions.ts:20-31,94-106`). No React live implementation found.

## Capability families

### Session list, detail, creation, and deletion

Flutter lists the current canonical scope, partitions resumable rows, opens a detail with the latest 50 structured messages, creates a local row plus SDK session, and hard-deletes with optimistic rollback (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:1876-1978,2064-2128,2810-2887`). React live mode can list chat sessions, fetch one detail, create with `profileId`, `cwd`, `name`, and isolation fields, preserve the returned `sdkSessionId`, and hard-delete with `removeWorktree: true` (`apps/web/src/gateway/sessions.ts:94-107,149-167`; `apps/web/src/store.tsx:213-275`; `apps/web/src/components/SessionRail.tsx:76-97,161,185-186`).

React therefore has the basic live create/detail/chat-list/hard-delete path. It does not have the non-chat list scopes, list synchronization, persistent close/archive/restore, or older-page paths listed above. Its bulk delete issues independent requests but closes the dialog immediately and does not aggregate partial failures (`apps/web/src/components/SessionRail.tsx:164,186`).

The server's hard delete stops the stream, optionally removes the worktree, best-effort deletes the engine session recursively, deletes the local row (whose message rows cascade), broadcasts `session.removed`, and returns 204 (`apps/api_server/src/controllers/agent_sessions_controller.ts:1547-1604`). This is the correct boundary for Phase 4 cleanup evidence, but the comments also show engine/worktree cleanup is best-effort, so the Phase 4 contract must assert residue rather than infer it from the 204.

### Composer and attachments

Both clients have a per-session draft, an optimistic user bubble, pending attachment chips, send-on-Enter, and a model override field. Only Flutter's live path sends attachments as canonical `parts`; React's live path sends only `data` and a profile-derived `{providerId, modelId}` override (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:2526-2615`; `apps/web/src/components/Composer.tsx:116-125`; `apps/web/src/store.tsx:278-303`).

The canonical WS input alternatives are `{v:1,type:'session.input',id,data}` or `{v:1,type:'session.input',id,parts:[...]}`. File parts use the persisted/engine vocabulary `{type:'file',mime,filename,url}`; text parts use `{type:'text',text}` (`apps/api_server/src/services/ws_gateway.ts:287-350`). `modelOverride` is deliberately per-turn and uses API-facing lower-camel `{providerId, modelId}` before the server resolves the SDK pair (`apps/api_server/src/services/ws_gateway.ts:353-357,752-780`).

### Structured streaming

The bridge emits distinct `message.part.updated`, `message.part.delta`, `message.updated`, `message.removed`, `message.part.removed`, `session.status`, and `session.removed` frames. Full parts are authoritative; deltas append by `messageId`/`partId`/`field`; message info carries role/tokens/cost; retry status is transient (`apps/api_server/src/services/opencode_stream_bridge.ts:1248-1435,1493-1519,1534-1598`). It writes structured message info and ordered parts to the local mirror as the events arrive (`apps/api_server/src/repositories/agent_session_messages_repository.ts:158-220,223-335,338-393`).

Flutter implements the corresponding message/part reducer. React implements only a first-delta placeholder and an idle-time detail replacement. Consequently React can show that output began, but cannot truthfully show the growing response or structured tool/reasoning/file state while the turn is working.

### Retry, cancel, resume, and reconnect

Flutter differentiates four operations: provider retry is an observed transient engine state; cancel aborts the current SDK turn; resume reattaches a resumable local row to its persisted SDK session; reconnect repairs the API/WS transport, resubscribes, and refetches (`origin/main@9fa2761:apps/desktop_flutter/lib/features/agents/controllers/agents_controller.dart:2159-2170,2361-2392,2500-2519,3156-3201`). React currently conflates all four with fixture/local status mutations and presentation timers. Phase 4 tests must keep these meanings separate.

### Reload persistence and transcript parts

The API is the transcript source of truth. It persists message rows keyed by `(session_id, sdk_message_id)`, stores canonical ordered parts in `parts_json`, normalizes timestamps to UTC, and returns structured pages with `parts`, `tokens`, `cost`, `nextCursor`, and `hasMore` (`apps/api_server/src/repositories/agent_session_messages_repository.ts:8-43,63-123,158-220,503-534`; API detail/page responses at `apps/api_server/src/controllers/agent_sessions_controller.ts:594-622,2369-2393`). Canonical persisted roles are `input`, `output`, and `system` (`apps/api_server/src/models/agent_session.ts:154-179`).

React does reload the selected live session from the API and stores only the selected local session ID in `rhythm-agents-live-selected-session` (`apps/web/src/store.tsx:46-48,102-108,141-149,213-220`). That is sufficient for basic text continuity, but the current mapper destroys structured part vocabulary and pagination metadata (`apps/web/src/gateway/sessions.ts:77-106,159-162`). Fixture session persistence in `rhythm-agents-fixture-sessions` is a separate localStorage behavior and is not evidence of live/API persistence (`apps/web/src/store.tsx:47,81-97,131-133`).

### Local versus SDK session identity

Every React REST route and WS frame must use the local Rhythm session `id`. The server alone resolves that local ID through `opencodeSessionMap` or the persisted `sdkSessionId` before invoking the engine (`apps/api_server/src/controllers/agent_sessions_controller.ts:326-334`; `apps/api_server/src/services/ws_gateway.ts:304-308,376-383`). Child transcript routing is the deliberate exception: the route contains the parent local ID plus a child SDK ID. No client may treat a profile ID, local session ID, SDK session ID, or model ID as interchangeable.

## Inventory conclusion

React/Electron has a real live spine for chat-scope list/detail/create/hard-delete, text input, first-fragment streaming, idle refetch, selected-session reload, and distinct `profileId`/local `id`/`sdkSessionId` fields. It does not yet have 12 Flutter capabilities listed at the top. Phase 4 cannot be declared complete by extending fixture tests around the existing controls; the contract must drive the live API, WebSocket, engine, persisted mirror, and cleanup boundaries named above.
